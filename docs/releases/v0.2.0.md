# v0.2.0 Release Notes

Released: 2026-08-02

## Release Summary

v0.2.0 prepares Quantitative Molecular Imaging Platform as a local research and
portfolio release for a selected public deidentified TCIA PET/CT workflow. The
release connects metadata ingestion, PostgreSQL registries, database-selected
DICOM pixel loading, NumPy/SciPy scientific operations, Matplotlib PNG artifact
generation, a Django REST Framework API, and a React/TypeScript visualization
workbench.

This release is not clinical software and must not be used for diagnosis,
treatment decisions, or production patient care.

## Main Capabilities

- Selected public deidentified TCIA PET/CT local workflow.
- PostgreSQL-backed imaging metadata and ingestion tracking.
- `LocalDicomFile` registry for server-side repository-relative DICOM file
  selection.
- Database-selected DICOM pixel loading for local scientific processing.
- Registered visualization artifact metadata through `VisualizationArtifact`.
- Portfolio README, screenshot, architecture documentation, and demo guide.

## Scientific Imaging Workflow

The implemented scientific workflow selects DICOM instances through PostgreSQL,
resolves the related local DICOM registry entry, loads the pixel array on the
server, applies DICOM rescale slope/intercept, and then runs one supported
operation:

- Rescale: CT values are reported in Hounsfield Units (`HU`); PT values are
  reported as `rescaled_pixel_value`.
- Gaussian filtering: SciPy Gaussian smoothing with a configurable positive
  sigma.
- Sobel gradient magnitude: gradient-magnitude output with supported display
  scaling.

PT values are not presented or inferred as SUV. Matplotlib renders generated
visualizations as PNG files, while PostgreSQL stores artifact metadata such as
operation, modality, units, display range, checksum, file size, and source
instance. PNG bytes and NumPy arrays are not stored in PostgreSQL.

## API And Frontend Features

- Read-only metadata APIs for overview, imaging, ingestion, analysis results,
  and registered visualization artifacts.
- Registered PNG responses served through artifact database IDs.
- Controlled `POST /api/v1/analysis/artifacts/generate/` endpoint for
  visualization generation.
- React/TypeScript workbench with artifact filters, generation controls,
  generated-artifact selection, list refresh, and deduplication.
- Browser access through registered artifact IDs and `image_url` values, not
  local paths.

## Safety And Privacy Boundaries

- Local filesystem paths are not exposed through the public API.
- Clients cannot submit DICOM paths, PNG paths, output paths, image bytes, or
  NumPy arrays.
- Raw DICOM files and generated PNG files remain local filesystem artifacts and
  are not included in Git.
- PostgreSQL stores metadata only; it does not store PNG bytes or scientific
  NumPy arrays.
- This release has no clinical validation, diagnostic accuracy claim,
  authentication layer, cloud deployment, or production-readiness claim.

## Current Limitations

- Research and portfolio software only; not a clinical system.
- No authentication or authorization.
- No upload workflow, SQL explorer, local filesystem browser, or arbitrary
  server-side path input.
- No browser-side DICOM reader or machine-learning inference.
- Local PostgreSQL data, selected DICOM files, and generated PNG files are not
  version-controlled.
- The scientific operations are intentionally narrow demonstrations for one
  selected two-dimensional DICOM slice.

## Upgrade Notes From v0.1.0

- Apply normal Django migrations.
- Reinstall or refresh Python dependencies from the project metadata.
- Run `npm install` in `frontend/` so package metadata remains synchronized.
- Local PostgreSQL data, DICOM files, and generated PNG files are not included
  in Git.
- No database schema migration should be invented for this release-preparation
  PR.
